# Demo 制作规则（每轮 demo 前必读）

> 本文件是唯一的 demo 规范。做新一轮 demo 前先读本文件 + `DEMO-INDEX.md`（找上一轮参考）。
> 定案日期：2026-07-19（用户直接指定）。

## 1. 目录与文件（每轮固定 3 份动态 demo，2026-07-20 起不再要求 00-all-pages.html）

每轮 demo 建一个文件夹 `docs/design/demo-YYYY-MM-DD/`（同日第二轮加 `-2`），内含 3 份自足 HTML（无外部依赖，双击即开，可点按钮走流程）＋ 1 份树状结构说明：

| 文件 | 内容 |
|------|------|
| `01-supervisor.html` | 主管端简单交互 demo |
| `02-lifeguard.html` | 救生员端简单交互 demo（含注册全流程） |
| `03-admin.html` | 平台管理员端简单交互 demo |
| `TREE.md` | **该轮 demo 的树状结构**：文件清单 + 三端页面层级（按页面 ID）+ 本轮相对上一轮的改动表；**已确认的端/页面在此标注"已确认，跳过，见 confirmed/xxx.html"，不用重做** |

> 全页静态总览 `00-all-pages.html` 已停用（2026-07-20 用户定案，只留三份动态 demo 即可）。若某轮所有端都已确认，允许该轮不新建 demo 文件夹，直接在 `confirmed/` 上做局部调整。

每轮做完：先更新本轮 `TREE.md`，再在 `docs/design/DEMO-INDEX.md` 顶部加一行索引。

## 1a. 已确认样式（`docs/design/confirmed/`，2026-07-20 用户定案）

某一端（或某个页面）的样式经用户明确认可后，把当轮该文件**复制**进 `docs/design/confirmed/`（文件名沿用 `0X-角色.html`，标题改注明"已確認樣式，定稿於 YYYY-MM-DD"）。规则：

- `confirmed/` 里的文件代表**当前已定案、不用再重做**的样式，是该端的事实来源。
- 之后新一轮 demo：已确认的端**不需要**再重新生成对应文件，只处理还在改动中的端；`TREE.md` 里注明"已确认，跳过"并指向 `confirmed/` 里的文件。
- 若确认后又要改（用户提出新要求），直接改 `confirmed/` 里的文件本体，不必重开一轮 demo 文件夹（除非改动大到需要新旧对比）。
- 当前进度：**三端（A/S/L）均已确认**。A 见 `docs/design/confirmed/03-admin.html`（定稿于 2026-07-20，基于 demo-2026-07-20 版本）；S 见 `docs/design/confirmed/01-supervisor.html`、L 见 `docs/design/confirmed/02-lifeguard.html`（均定稿于 2026-07-21，基于 demo-2026-07-21 R3 同日修订版）。
- **遗留事项**：`confirmed/03-admin.html` 本体是旧蓝配色，R3 的 iOS 明暗新配色**未回写进去**（S/L 的 confirmed 版已经是新配色）；管理员端要不要补套新配色待用户决定，决定前三端配色不完全一致属已知差异，不是漏改。

## 2. 统一比例（19.5:9）

手机演示框统一用 **19.5:9** 宽高比，不再要求多机型切换按钮。基准宽度固定 **402px**，对应高度＝402 ÷ 9 × 19.5 ＝ **871px**（四舍五入取整数）；若某份 demo 里已有的默认宽度不是 402，则以该文件已有宽度为基准，按 19.5:9 重新算高度，保持视觉一致。

## 4. 配色：iOS 明暗（日/夜）——2026-07-21 用户定案，取代旧「界面个性化」

- **旧方案已废**：原「风格 A 卡片式 / C 磁贴式 + ≥4 主题色（蓝/青/橙/紫）」个性化选择器**全部删除**（含 `data-style`/`data-color` CSS/JS/DOM 与 S8 选择器）。SPEC §8 已同步。
- **新方案**：三端统一 **iOS 明暗（日/夜）配色**，用 CSS 变量 + `body.dark` 覆盖实现。默认浅色（day）；提供 **日/夜切换**两处联动——顶栏一个 `☀︎/☾` 按钮 + 「我的/设置」页一行「深色模式」开关。
- 顶栏改 **iOS 系统栏风格**（`var(--navbar)` 浅底 + 底部 1px 发丝线，非旧版实心主色蓝顶）；卡片、底部 tab、按钮均走 token。
- 参考色值（light / dark）：主色 `#007aff`/`#0a84ff`、背景 `#f2f2f7`/`#000`、卡片 `#fff`/`#1c1c1e`、正文 `#1c1c1e`/`#fff`、警示 `#ff3b30`/`#ff453a`、成功 `#34c759`/`#30d158`、发丝线 `#e5e5ea`/`#38383a`。
- 正式版：日/夜偏好存在用户账号（跟随系统亦可），全站生效。

## 4a. 更表格子与缩放（2026-07-21 用户定案）

- **每人一格（cell）**，一天里 cell 数量＝该泳池当天所需救生员人数；主管月更表按「位置 index」列排（demo 固定 4 列）。
- **字号可调**：表格上方 `A−/A＋` 改 `--cellfs`；`.xls` 容器 `overflow:auto`，字大装不下自动出滚动条。
- **假期着色**：周六日红底**只落在「日期 cell + 星期 cell」**，不整行染红。
- 主管端具备：格子间**拖拽交换**、**一键排更**（填缺）、**一键整理**（竖直对齐到各自主列，算法见对应轮 TREE/开发日志）、缺人格点击/长按**招募此格**、**月份选择**。救生员端仅复用视觉+缩放，单人无拖拽。

## 5. 测试壳规则（demo 与正式代码通用，2026-07-19 用户定案）

- **WhatsApp 反向验证**：暂时只写壳——界面显示验证码，点跳转按钮后 **3 秒倒数自动通过**；界面注明【测试壳】。
- **证件 OCR**：暂时只写壳——照片任意上传即通过。
- 正式接入 Meta / OCR 时机由用户另行通知，到时补齐。
- 代码注释标记（写代码阶段强制）：
  - `【壳-待补】`：正式功能占位，等用户通知补齐
  - `【长期测试】`：长期保留的测试代码
  - `【临时测试-用完即删】`：测完必须删，功能收尾时逐一清理

## 6. 底部导航角标（全局功能，2026-07-20 用户定案，参考微信）

三端（主管/救生员/管理员）底部主要分页 Tab 右上角用**小圆形红色角标**显示未读/待办数量，逻辑同微信底部 Tab 红点，**所有账号类型必备**：

- **当前所在分页自动清零**（`.on` 不显示角标），离开后若又有新内容则重新出现；数量为 0 不显示，超过 99 显示 `99+`。
- 数量含义按分页 + 角色（对齐 SPEC §8 表）：总览/招募＝新出现且未读的消息或事物；更表＝缺人的更数量（主管）／新入表·变更班次（救生员）；讯息＝有未读消息的**人数**；工资＝主管未结清账单数／救生员待确认收款笔数；我的＝账号提醒（通常 0，但界面须具备该能力）；审核（管理员）＝待审证件数。
- demo 实现：`.nb` 角标 CSS + `const BADGE={label:数量}` + `renderBadges()`（按 Tab 文字匹配、跳过 `.on`、0 隐藏、>99 显示 99+），状态变化时重调。正式版由后端未读/待办计数实时驱动。

## 7. 共享组件（2026-07-21 起，跨端一致，写代码时沿用同名 class）

- **筛选器 `.filt`**：可展开面板，含工种（短工/长工）、地区级联（港岛/九龙/新界→具体区）、显示时薪开关；主管版多「只我发布/排除我」来源行。用于主管 S1/S2/S6、救生员 L2。
- **招募卡片 `.reccard`**：**最大字＝地区级联**（`.recloc`），其下才是时间/备注/时薪；情形 B 保密不露泳池名，自己发布带管理掣。用于主管 S1、救生员 L2。
- **工资大卡片 `.wcard`**：每人一大块，点整卡进详情；确认掣样式＝「報名」实心主色掣；结清也显金额+绿字已結。主管 S6 外层显姓名+金额；救生员 L4 外层只显主管名+总额。
