# Demo 制作规则（每轮 demo 前必读）

> 本文件是唯一的 demo 规范。做新一轮 demo 前先读本文件 + `DEMO-INDEX.md`（找上一轮参考）。
> 定案日期：2026-07-19（用户直接指定）。

## 1. 目录与文件（每轮固定 4 份）

每轮 demo 建一个文件夹 `docs/design/demo-YYYY-MM-DD/`（同日第二轮加 `-2`），内含 4 份自足 HTML（无外部依赖，双击即开）＋ 1 份树状结构说明：

| 文件 | 内容 |
|------|------|
| `00-all-pages.html` | 全部页面静态总览（一页看完所有界面） |
| `01-supervisor.html` | 主管端简单交互 demo（可点按钮走流程） |
| `02-lifeguard.html` | 救生员端简单交互 demo（含注册全流程） |
| `03-admin.html` | 平台管理员端简单交互 demo |
| `TREE.md` | **该轮 demo 的树状结构**：文件清单 + 三端页面层级（按页面 ID）+ 本轮相对上一轮的改动表 |

每轮做完：先更新本轮 `TREE.md`，再在 `docs/design/DEMO-INDEX.md` 顶部加一行索引。

## 2. 真机尺寸（必须可切换）

手机框按真实机型逻辑分辨率（CSS 像素），顶栏提供切换按钮：

| 机型 | 尺寸 |
|------|------|
| iPhone SE | 375 × 667 |
| iPhone 17（默认） | 402 × 874 |
| iPhone 17 Pro Max | 440 × 956 |
| Android 常见中端 | 360 × 800 |

## 3. 页面 ID（跨轮固定，页面右上角角标显示）

用户用 ID 指哪改哪。已分配：

| 端 | ID |
|----|----|
| 主管端 | S1 首页（**2026-07-20 起**：今明缺人总数＋待处理＋招募情报 L2 卡片组件置底＋发布招募右下角悬浮掣；曾于 2026-07-19 短暂并入天气栏与 S2，R2 已回退）｜S2 更表·泳池一览（**2026-07-20 R2 恢复使用**，语义未变，属复用同语义 ID）｜S3 月更表（Excel 式垂直）｜S4 讯息（会话列表→聊天，可筛选最新收到）｜S5 待处理报名｜S6 工资｜S7 发布招募｜S8 设置（界面个性化） |
| 救生员端 | L1 注册/登录｜L2 搵工（招募列表）｜L3 我的更表｜L4 我的工资｜L5 聊天 |
| 管理员端 | A1 证件审核｜A2 用户列表 |

新页面接着编号（S9…、L6…、A3…），**旧号永不复用**；页面被砍掉时 ID 作废留空（S2 即为首例）。

## 4. 风格与主题色切换（对应 SPEC §8 界面个性化）

每份 demo 顶栏都有：风格「A 卡片式 / C 磁贴式」切换 + ≥4 个主题色（蓝 #2a6f97 / 青 #0e7c7b / 橙 #d9660e / 紫 #5f55c5），用 CSS 变量 `--p` / `--psoft` 实现。正式版里这就是主管设置页（S8）的个人选项。

## 5. 测试壳规则（demo 与正式代码通用，2026-07-19 用户定案）

- **WhatsApp 反向验证**：暂时只写壳——界面显示验证码，点跳转按钮后 **3 秒倒数自动通过**；界面注明【测试壳】。
- **证件 OCR**：暂时只写壳——照片任意上传即通过。
- 正式接入 Meta / OCR 时机由用户另行通知，到时补齐。
- 代码注释标记（写代码阶段强制）：
  - `【壳-待补】`：正式功能占位，等用户通知补齐
  - `【长期测试】`：长期保留的测试代码
  - `【临时测试-用完即删】`：测完必须删，功能收尾时逐一清理
