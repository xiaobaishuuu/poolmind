## 1. 产品概述

PoolMind 是面向香港救生员外判公司的管理系统。现有业务完全跑在 WhatsApp 上：主管群发招募 → 救生员私信报可上班时间 → 主管手动排更、发薪时手动逐人算工资。

**产品目标**：主管只负责"和人对接"（谈工资、按确认、处理异常），其余人事杂务——汇总可用性、排更、算工资、追支付确认——全部由系统自动完成。主管的人工介入仅剩四件事：谈工资、按确认、调整更表异常、去银行转账。

**交付分期**：第一期为响应式网页全功能（点 WhatsApp 链接即用，无需装 App）；第二期出原生 App（iOS + Android，非套壳 WebView）。API 自第一期起按前后端分离设计。本期单公司自用，数据模型预留多公司（多租户）隔离，日后可开放其他判头注册。

## 2. 角色

| 角色 | 说明 |
|------|------|
| **平台管理员** | 独立角色（可多个），与业务权限完全分离。职责：逐个人工审核救生员证（认证状态机）、处理身份类兜底（OCR 反复失败、忘密码+换号并发等）。为平台化预留。 |
| **主管（判头）** | 可分级：主管可创建子主管账号并分配屋苑泳池，形成垂直链。权限 = 自己管辖泳池 + 下级全链泳池。工资单按主管管辖范围生成。顶级主管账号在系统初始化时创建。 |
| **救生员** | 通过招募链接注册。报名、上更、确认收款。 |
| **主管兼救生员** | 主管上传资历（同样过 OCR + 管理员认证）后可把自己排进更表、看自己工资；自付工资直达"双向已确认"（不可撤销、无 7 天倒计时）。 |

## 3. 账号与身份

### 3.1 三层名字体系
- **用户名**：登录 ID。注册时查重，**永久不改、永不释放复用**（含注销账号的用户名）。
- **对外显示名**：用户自设（如"阿明"），聊天、报名列表、更表、工资单等日常界面一律显示它；随时可改、无需唯一。
- **真实姓名**：只出现在个人资料页（对可查看该用户的人开放）；认证、OCR、身份锚定基于真实姓名与证号。

### 3.2 注册（全系统唯一的一种注册）
五样一次过 + 一个可选项，约 2 分钟：
1. 用户名（查重）
2. 密码
3. 真实姓名
4. 救生员证照片 → **OCR 自动比对**证上姓名与所填姓名，一致才放行；反复失败转平台管理员人工通道
5. **WhatsApp 反向验证**：页面显示一次性验证码 + wa.me 跳转按钮，用户从自己的 WhatsApp 发验证码给系统号（免费），验证号码真实可达并绑定为联系号码
6. （可选）对外显示名，不填默认用真实姓名

注册即建账号【未认证】。入表时**无需再补任何资料**。浏览招募免登录；点「报名」或「联系以报更」时强制登录或注册——**聊天没有访客模式**。

### 3.3 认证状态机（平台管理员终审）
`未认证 →（管理员人工审核证件）→ 已认证 / 驳回`；证件续期重传 → `待复审`（不影响既有排班与工资）。

- 未认证**不卡业务**：可聊天、报名、被确认入表；但主管界面全程高亮"未认证"，可点开查看证件图自行把关。
- 驳回后全界面红色警告；排不排由主管负责（与证件过期同一原则）。

### 3.4 登录与凭证
- 登录 = 用户名或手机号（仅用于找到账号）+ 密码；可选 passkey（Face ID/指纹）。**手机号永远不能单独当钥匙。**
- **忘记密码（全自助双闸，零 SMS 零人工）**：① 从绑定号 WhatsApp 发一次性验证码给系统号（校验：验证码正确 且 发信号码=绑定号）→ ② 重传救生员证，OCR 自动比对档案姓名/证号 → 双闸通过自动发重置链接。兜底（OCR 反复失败 / 忘密码+已换号并发）才转管理员。
- **忘记用户名**：输手机号或证号 → 脱敏提示（如 `wai***23`），不构成登录凭证。
- **换手机号**：登录态下改号 + 新号反向 WhatsApp 验证。号码是纯联系字段，被电讯商回收/易主零风险。

### 3.5 身份原则与保护态
- 身份三层：**密码管进门；WhatsApp 反向验证管"号码是你的"；证件 OCR + 管理员管"人是你"**。证号为全局唯一身份锚（查重、找回、改名均锚定证号）。
- **保护态**：有未结清工资或未来排班的账号，禁止一切自动注销/释放类操作，一律转人工。
- 18 个边际个案（号码回收、重复注册、冒用证件、改名、换证、盗号、注销、失联、双角色等）已逐一验证收敛于本方案（详见访谈档案 2026-07-14）。

## 4. 招募与报名

### 4.1 招募链接与分层披露
- **每个主管一条长期通用链接**。落地页 = 全平台招募搜索页，默认预设"该主管"过滤条件（先看到他发布的所有在招更）；过滤可清除，可浏览/搜索所有主管公开的在招更。纯浏览免登录。
- **分层披露**：发招募时主管自选公开哪些字段（日期/区域/更次时间/地铁站/泳池模板备注等，也可选择公开工资）。行业惯例不在公海讲具体泳池和工资（防同行截胡、保议价空间、防员工比价）。
- **WhatsApp 文案模板**：系统按公开字段自动生成招募文案（含链接），主管一键跳转 WhatsApp 转发到群（wa.me 免费机制；系统不直接向群发消息）。

### 4.2 报名（要约—接受统一模型）
入表三要素：**泳池 + 更次 + 时薪**；**最后一步永远是主管确认（主管是唯一入表触发者）**。

- **情形 A（帖内公开泳池/工资）**：更列表显示直接「报名」按钮（也可进聊天）→ 点报名（接受公开要约）→ 主管同意 → 入表（时薪默认带出公开价，主管可改）。
- **情形 B（信息保密）**：更列表只显示「联系以报更」按钮 → 进聊天商议 → 主管发**泳池详情卡片**（含泳池+更次+时薪，此时才露具体屋苑）→ 救生员点卡片「接受」→ 主管最终确认 → 入表。

规则：
- 长更报名勾选到该月的**更次级别**（更次由泳池模板预定义）；短更报名即视为该更次可用，与长更本质相同。
- 多人报同一短更：按报名时间顺序展示；主管点进报名列表逐个用内置聊天议价。
- **一人多报与"抢人"**：救生员可同时报多个短更。任一主管确认入表后，该人从其他泳池的待确认列表隐藏（冲突隐藏）；该确认被取消则恢复显示。
- 未被确认的报名（长更或短更），救生员可随时撤回或取消，**等同从未报名**：各处列表静默消失、不通知、不留痕。

### 4.3 站内聊天
主管×救生员为**人对人永久会话**（类似 WhatsApp）：所有报名、详情卡片、议价历史在同一对话框，永久保留。聊天只是沟通工具——**不做 AI 读聊天提取工资**，时薪由主管确认时手动输入（界面显示参考价）。

## 5. 泳池与模板

- 多个屋苑泳池，各自的更次时间、人数需求不同，均按主管管辖链归属。
- 创建泳池必须填**至少一个模板**；模板可建**任意多个、自由命名**（"夏季/冬季"只是名字）。
- 模板内容：救生员人数（位置数）、默认时薪、备注（可作为招募公开字段）、**按星期几的更次定义**（如周一早更 7:00–15:00、周三无更）。
- 月更表创建时**选定模板**；创建后改模板可选「某日之后生效」或「全部改变」，产生的排班冲突列给主管处理。
- 每个泳池可设**偏好名单**（成员 + "空位中至少 N 个来自名单"的规定）。

## 6. 更表与排班

### 6.1 结构
- 更表页先显示管辖的**所有泳池一览**，点入单池月更表（日历视图）。
- **最小单位 = 时段分配**（谁、哪个位置、几点到几点、什么价）。格子（泳池×天×位置）是展示外壳：**默认一人上整天**（显示一个显示名）；需要时**拆段**（切点自由选），一格多人分时接力（如 阿明 7–14 / 阿强 14–22），各按自己时段时数×时薪计薪。拆段是更表临时操作，不动模板。
- **更表即考勤**：不做打卡/GPS。排入更表即默认出勤；请假/旷工等异常由主管手动改表；名字在更表上就计薪。

### 6.2 编辑约束
- **拖拽硬约束**：救生员名字只能拖进他报过可上班的更次（前后端双重校验）。两个例外：① 当天已在更表上的人可跨管辖泳池调动（交换）；② 当天没班的人经"请人卡片"接受 + 主管确认后入表。
- **过去锁死**：每天午夜 00:00 后，过去日期的更表（时数/时薪/人员）不可改；仅可添加**加钱/扣钱调整项（必填原因）**，工资单自动重算。

### 6.3 一键排班
优先级：① 偏好名单成员最优先且满足最少 N 人规定 → ② 连续性（同一人同一泳池连续上更）→ ③ 其他。无法完全满足时尽力满足并照样给出方案，由主管手动收尾。

### 6.4 排班工具箱（三原语：拆段 / 改段的人 / 对调）
- **交换**：月更表**长按救生员** → 弹出菜单（交换、移除等）→ 选「交换」→ 泳池列表（附各池救生员名字、上班时间）→ 选中后**双表并排**：目标池当天详细时间表 × 本池该救生员当天细节表，拖拽对比调整，画面内可直接调涉及者的工资；两人都上整天时有「**直接交换**」一键——各自接手对方时段原本的样子（时段跟泳池走、人流动，泳池开放时间不同不会错位）→ 确认生效 → 通知双方。**主管直接换，无需救生员同意**；时薪按三层规则对新泳池重算，预览显示、可当场改。
- **请人补空位**：点空位（或一键全选所有空位）→ 列出这一天/这些天**不用上班且合作过**（进过该主管更表）的人 → 勾选一人或多人发泳池详情卡片 → 对方接受后进待确认列表 → 主管确认才入表（多人接受同一空位由主管挑）。

### 6.5 变动与通知
- 救生员取消**已确认班次**：二次确认框（提示"将立即通知主管"）→ 立即通知该泳池管辖主管。
- 短更被本人取消 → 班次重新开放，恢复之前因冲突隐藏的其他报名者。
- 长更排班被本人取消 → 该格空缺，主管用排班工具箱处理。
- 救生员不想上班需逐个取消所报班次。

## 7. 工资与支付确认

### 7.1 计算
- 每晚 00:00 自动汇总：应付 = Σ（时薪 × 时段分配时数）+ 调整项，生成/刷新工资单（含每日明细）。
- **时薪三层覆盖**：单日单独改（更表每格可编辑）> 该救生员×该泳池绑定价（谈一次自动沿用，主管可手动改）> 泳池模板默认价。
- **价格对救生员不可见**：默认价只是主管端参考；救生员任何界面看不到价格，只在自己工资单看到自己谈定的时薪。

### 7.2 界面
- 主管端：按管辖泳池看每个救生员月度应付；**工资页第一眼即见未结清余额**；可下钻单日明细单日确认，或整人一键确认。
- 救生员端：自己的更表 + 工资单（按主管分组），可单日确认收款。
- **救生员端更表——同事联系（2026-07-17 补充）**：每个上班日可见自己所上的泳池、当日**同池同事**（显示名）及该池**管辖主管**；每人旁有按钮**一键跳转其 WhatsApp**（wa.me）。可见与可联系范围仅限"同一天同一泳池共事者 + 该池管辖主管"；wa.me 跳转会暴露号码，此为用户确认接受的设计。
- **Excel 导出**：按月/按泳池/按人（含每日明细、调整项、支付状态）。不做 PDF。
- **转账在系统外**：主管自行银行转账，系统只做金额计算与确认跟踪，不接支付渠道。

### 7.3 支付确认状态机
- 待支付 →(主管确认)→ 支付方已确认
- 待支付 →(员工确认)→ 员工已确认（待自动），启动 7 天计时，7 天后自动替主管确认
- 支付方已确认 →(员工确认)→ 双向已确认
- 员工已确认（待自动）→(主管确认)→ 双向已确认，终止计时
- 员工已确认（待自动）→(7 天到期)→ 自动确认支付
- 待支付 →(主管忽略)→ 已完结（忽略）
- 待支付 →(主管兼救生员自付)→ 双向已确认（系统自动代完成员工端，无倒计时）
- 撤回：支付方已确认→主管可撤回；员工已确认（待自动）→员工可撤回；双向已确认 / 自动确认 / 已完结（忽略）一律不可撤销；自付确认不可撤销。

## 8. 主管首屏（仪表盘）

1. 今明两天缺人的更（点入直接处理）
2. 待处理报名 / 未读消息
3. 今日各池在岗一览

未结清余额不在首屏（在工资页）。证书到期/过期提醒：到期提醒双方；过期在聊天框、资料页、更表三处高亮，**只提醒不禁排**。

**界面配色（2026-07-21 修订，取代 2026-07-18「界面个性化」）**：原「界面风格（卡片/磁贴）＋主题色（≥4 种）」个性化方案**已废除**。改为三端统一 **iOS 明暗（日/夜）配色**：用户可在设置中切换**深色模式**（浅色 day / 深色 night，亦可跟随系统），选择存于账号、只影响自己界面；全站其余设计元素（字体、间距、组件）保持统一设计基因。参考色值与实现见 `docs/design/DEMO-RULES.md` §4，样稿见 `docs/design/demo-2026-07-21/`。

**底部导航角标（2026-07-20 补充）**：三端（主管 / 救生员 / 管理员）底部主要分页 Tab 右上角用**小圆形红色角标**显示未读/待办数量，逻辑与微信底部 Tab 红点一致——**当前所在分页自动清零**（不显示角标），离开后若又有新内容则重新出现；数量为 0 不显示，超过 99 显示 `99+`。角标数字含义按分页 + 角色语义决定：

| 分页（示例） | 角标数字来源 |
|------|------|
| 招募（首页） | 新出现且未读的消息或事物数量 |
| 更表 | 缺人的更数量（主管）／新入表・变更的班次数量（救生员） |
| 讯息 | 有未读消息的**人数**（不是消息条数） |
| 工资 | 主管端：已到结清月日期但仍未结清的账单数（+1 计法）；救生员端：待确认已收款的笔数 |
| 我的 | 账号相关提醒，通常为 0，但界面须具备该能力 |
| 审核（管理员） | 待审证件数量 |

正式版角标数字由后端未读/待办计数实时驱动。

## 9. 通知（第一期）

全免费组合：**站内通知 + Web Push + wa.me 跳转**。
- 关键动作（取消已确认班次等）在动作方界面强制弹 WhatsApp 跳转（预填消息、收件人为对方），接受"对方不按发送则收不到"的残余风险（站内记录始终保留）。
- 不接 WhatsApp Business API、不发 SMS。第二期 App 原生推送解决保证送达。
- 备查费率：WhatsApp API 实用类约 HK$0.13–0.2/条，SMS 约 HK$0.5/条，Web Push/wa.me 免费。

## 10. 安全与合规（香港上架要求）

> 「本項目本地開發與上線部署時，數據庫需啟用 AES-256 靜態加密（Encryption at Rest）。」

> 「用戶上傳的救生員證照片，必須儲存在非公開目錄（Private Storage），後台管理員需通過權限驗證後，由後端以 Stream（串流）形式讀取，嚴禁生成公開 URL。」

- **数据库静态加密**：本地开发与生产部署环境的数据库均须启用 AES-256 Encryption at Rest。
- **证件照片私有存储**：救生员证照片存放于非公开目录（Private Storage）；任何读取（含平台管理员审核、主管查看证件图、OCR 处理）必须先通过后端权限验证，由后端以 Stream 串流返回；**严禁生成公开 URL**（含带签名的长效公开链接）。
- 沿用既有隐私规则：价格对救生员不可见；真实姓名仅资料页可见；分层披露防泳池/工资信息外泄。

## 13. 验收标准

### 泳池与招募
- [ ] 主管可创建屋苑/泳池，含 ≥1 个自由命名模板（人数+默认时薪+备注+按星期几更次定义）；月更表创建时选模板；改模板可选"某日后生效/全部改变"并列出冲突
- [ ] 主管可发布长更/短更招募并获得可分享链接；系统生成 WhatsApp 文案一键跳转转发
- [ ] 每个主管有自己的长期通用链接；落地页为全平台招募搜索页，默认预设该主管过滤且可清除；只显示各主管勾选公开的字段

### 注册与账号
- [ ] 浏览招募免登录；点"报名/联系"时强制登录或注册；注册时证件 OCR 与姓名一致才放行，不一致被拒并提示重拍
- [ ] 注册五要素 + OCR 姓名比对 + WhatsApp 反向验证全流程可走通；用户名永久唯一且永不复用
- [ ] 对外显示名在聊天/报名列表/更表/工资单等日常界面生效；真实姓名仅在个人资料页显示；显示名可随时修改且不要求唯一
- [ ] 未认证/已认证/驳回/待复审状态机生效；未认证可入表但全程高亮；驳回红色警告
- [ ] 忘记密码双闸自助重置端到端可用（含"发信号码=绑定号"校验与证件 OCR 比对），无需管理员参与
- [ ] 保护态账号（未结工资/未来排班）无法被注销或自动化释放
- [ ] 顶级主管账号由初始化流程创建；数据模型含公司/租户维度（本期单租户运行）
- [ ] 子主管只能看到/操作自己管辖链内的泳池、更表、工资单
- [ ] 主管兼救生员：上传资历后可排自己进更表，自付确认直达双向已确认且不可撤销

### 报名与聊天
- [ ] 情形 A：有直接"报名"按钮，主管同意即入表（时薪带出公开价可改）；情形 B：只有"联系以报更"，卡片被接受后仍需主管最终确认；任何入表动作都由主管触发
- [ ] 聊天为人对人永久会话；泳池详情卡片含接受按钮，未发卡片前救生员看不到具体屋苑
- [ ] 一人多报：A 主管确认后该人从 B 池待确认列表隐藏；A 取消后恢复显示
- [ ] 取消未确认报名（长更/短更）后各处列表无痕消失，不发任何通知

### 更表与排班
- [ ] 更表页先显示管辖泳池一览，点入单池月更表
- [ ] 更表拖拽无法把人放进未报可用的日子（前后端双重校验；交换/请人两例外按规则放行）
- [ ] 格子默认一人整天；可自由切点拆段，一格多人分时接力，各按时段时数计薪；过去锁定规则对每段生效
- [ ] 一键排班满足：偏好名单最少人数 → 连续性 → 尽力而为并展示方案
- [ ] 长按更表中救生员弹出操作菜单（交换/移除等）
- [ ] 交换全流程：泳池列表（附人名+时间）→ 双表并排拖拽 → 可当场调工资 → 整天对整天有"直接交换"一键（各自接手对方原时段）→ 确认生效并通知双方；无需救生员同意
- [ ] 请人补空位：单个空位或全选空位 → 列出当天空闲且合作过的人 → 发详情卡片 → 接受后进待确认列表，主管确认才入表
- [ ] 取消已确认班次：有二次确认框，确认后管辖主管立即收到通知；短更取消班次重开并恢复被隐藏报名者；长更取消该格空缺
- [ ] 救生员报名勾选到更次级别；工资时数取自时段分配时长

### 工资
- [ ] 每晚 00:00 定时任务刷新工资单；金额 = Σ(时薪 × 时段时数) + 调整项
- [ ] 时薪三层解析正确：单日改价 > 人×池绑定价 > 泳池默认价；绑定价谈一次后新排班自动沿用
- [ ] 救生员任何界面看不到默认价/他人价格；自己的时薪只在工资单可见
- [ ] 工资页第一眼可见每个救生员未结清余额；单日确认与整人确认即时更新余额
- [ ] 支付状态机 7 条转换 + 4 条撤回规则全部有自动化测试覆盖（含 7 天定时自动确认）
- [ ] 午夜后过去日期更表不可编辑；仅可添加加钱/扣钱调整项（必填原因），工资单自动重算
- [ ] 工资报表可按月/按泳池/按人导出 Excel（含每日明细、调整项、支付状态）
- [ ] 救生员端可见自己更表与按主管分组的工资单，可单日确认收款
- [ ] 救生员端更表每个上班日显示泳池、当日同池同事与管辖主管，均有一键跳转 WhatsApp 按钮；非同池同日者互相不可见联系方式

### 首屏、通知与合规
- [ ] 主管首屏：今明两天缺人的更、待处理报名/未读消息、今日各池在岗一览（未结清余额在工资页）
- [ ] 主管设置页可切换深色模式（iOS 明暗/日夜配色，可跟随系统），仅影响本人视图，刷新后保持
- [ ] 三端（主管/救生员/管理员）底部导航 Tab 具备未读/待办红色角标：当前所在分页自动清零、离开后有新内容重新出现、数量为 0 不显示、超过 99 显示 `99+`，各分页数字来源符合规格定义（招募=未读消息或事物、更表=缺人/新变更、讯息=未读人数、工资=未结清账单数/待确认收款笔数、审核=待审证件数）
- [ ] 证书到期提醒双方；过期高亮出现在聊天框、资料页、更表三处；不阻止排班
- [ ] 第一期通知：站内 + Web Push + 关键动作强制 wa.me 跳转预填消息
- [ ] 全站繁体中文、金额显示 HKD、手机浏览器（375px）可完整操作
- [ ] **数据库（本地开发与生产）启用 AES-256 静态加密，可出示配置证据**
- [ ] **证件照片存于 Private Storage；读取需权限验证并经后端 Stream 返回；扫描确认无任何公开 URL 可直达证件图（含签名长链）**
